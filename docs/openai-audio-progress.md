# OpenAI Audio provider progress

- Goal: add the fourth Annotation Editor provider, OpenAI Audio, with speech, IPA, draft/save semantics, playback, canonical persistence, and automatic cross-client WebDAV asset sync.
- Completed milestones:
  - Shared protocol: added and validated the `audio` material enrichment in Dart and TypeScript; canonical merge, update, sticky tombstone, and unknown-field preservation are covered.
  - Provider and settings: added OpenAI speech + direct IPA generation services and configurable Audio model/voice in both clients.
  - Editor integration: connected Audio as the fourth provider in both annotation editors and selection-action surfaces. Generated bytes remain draft-local until Save; Save retains the annotation UUID and enrichment identity while persisting canonical IPA and asset metadata.
  - Binary persistence and synchronization: both clients verify byte length and SHA-256, store generated MP3 bytes atomically below `annotation-assets/audio/`, play saved/downloaded assets from local storage, and automatically upload/download immutable assets below the configured WebDAV root. Local mutation uploads the asset before publishing its JSON reference; pull/merge downloads remote-only assets afterward. Tombstoned annotations and enrichments never trigger asset transfer.

- Important design decisions:
  - Audio is a material enrichment with `kind: audio` and uses the existing last-write-wins/sticky-tombstone semantics.
  - Binary data is external. Shared state contains a safe relative `annotation-assets/audio/<asset>` reference plus format, MIME type, byte length, and SHA-256.
  - Required audio fields are `ipa`, `voice`, `model`, and `audio`; unknown fields remain round-trippable.
  - Speech and IPA requests run together; IPA is generated directly by an OpenAI text model, never by speech-to-text.
  - Both clients use the existing OpenAI API credential. Speech defaults to `gpt-4o-mini-tts` / `alloy` and MP3.
  - The shared remote location is `<configured WebDAV root>/annotation-assets/audio/<asset>`; each client's local root remains private.
  - Audio assets are immutable and content-verified. Lingua uses conditional create and the existing exclusive-lock fallback when a server rejects `If-None-Match` creation.
  - Binary garbage collection is intentionally deferred: tombstones stop transfer but do not delete shared or local immutable bytes.
